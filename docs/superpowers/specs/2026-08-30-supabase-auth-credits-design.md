# Регистрация пользователей и кредиты через Supabase

Дата: 30 августа 2026 года  
Статус: согласовано по разделам, ожидает итогового подтверждения пользователя

## 1. Цель

Добавить в существующий учебный сервис обязательную регистрацию и вход. Каждый новый пользователь получает 5 кредитов. Один новый анализ рынка вакансий расходует 1 кредит.

Решение должно оставаться простым, работать на бесплатных тарифах Supabase и Vercel и не ухудшать уже существующий поиск вакансий и резервный локальный отчёт при недоступности LLM.

## 2. Согласованный пользовательский сценарий

1. Гость при открытии сайта попадает на отдельную страницу входа и регистрации.
2. Пользователь регистрируется по email и паролю длиной не менее 6 символов.
3. Подтверждение email на первом этапе отключено: после регистрации пользователь сразу входит в сервис.
4. База автоматически начисляет новому пользователю 5 кредитов.
5. После входа пользователь видит основной сервис. В шапке показываются его email, остаток кредитов и кнопка «Выйти».
6. Новый анализ вакансий расходует 1 кредит.
7. Просмотр результата, сохранённого в локальном кэше браузера, не расходует кредит.
8. Один повторный запрос к ИИ после ошибки анализа не расходует дополнительный кредит.
9. Когда кредитов не осталось, запуск нового анализа блокируется и показывается сообщение «Кредиты закончились».
10. Покупка, автоматическое пополнение и платные тарифы в эту версию не входят.

## 3. Интерфейс

### Страница авторизации

- Два режима на одной простой странице: «Войти» и «Регистрация».
- Поля: email и пароль.
- Понятные русские сообщения: неверный пароль, email уже зарегистрирован, слишком короткий пароль, временная ошибка.
- Кнопка блокируется на время запроса, чтобы форма не отправлялась повторно.
- Визуальный стиль продолжает существующий интерфейс сайта.
- Three.js и 3D-анимация не используются: они не помогают основному сценарию и излишне усложняют учебный проект.

### Основной сервис

- Неавторизованный пользователь не может открыть интерфейс анализа или вызвать его API.
- В шапке отображаются email, баланс и выход.
- Старого пароля или отдельного пароля для запуска анализа в форме поиска нет. Пароль используется только для входа в аккаунт.
- При нулевом балансе кнопка анализа отключена.
- После успешного списания баланс на странице обновляется без перезагрузки.

## 4. Архитектура

### Авторизация

- Используется Supabase Auth с email и паролем.
- Для Next.js используется серверная cookie-сессия через `@supabase/ssr`.
- Защита выполняется в двух местах: при открытии закрытых страниц и повторно внутри каждого серверного API-маршрута.
- Конкретная реализация обновления cookie и маршрутизации сверяется с локальной документацией установленной версии Next.js 16 перед написанием кода.

### Данные

Минимальная таблица `user_credits`:

- `user_id uuid primary key` — ссылка на `auth.users(id)` с каскадным удалением;
- `credits integer not null default 5` с ограничением `credits >= 0`;
- `created_at timestamptz`;
- `updated_at timestamptz`.

Триггер на создание записи в `auth.users` автоматически создаёт строку `user_credits` с 5 кредитами. Клиент не передаёт начальный баланс и не может назначить его самостоятельно.

Для связи бесплатного повтора ИИ с уже оплаченным анализом создаётся минимальная таблица `analysis_runs`:

- `id uuid primary key`;
- `user_id uuid` — владелец запуска;
- `query text` и `location text` — параметры поиска;
- `ai_retry_used boolean default false`;
- `created_at timestamptz`.

Содержимое вакансий и отчёта в Supabase не сохраняется. Эта таблица нужна только для подтверждения списания и одного бесплатного повтора ИИ.

### Безопасность базы

- На обеих таблицах включается Row Level Security.
- Пользователь может читать только свои строки по условию `auth.uid() = user_id`.
- Из браузера нельзя напрямую менять баланс или флаг повтора.
- Списание выполняет одна атомарная SQL-функция: она берёт `auth.uid()`, уменьшает баланс только при `credits > 0`, создаёт `analysis_runs` и возвращает идентификатор запуска и новый баланс.
- Получение бесплатного повтора выполняет отдельная атомарная функция, которая разрешает один повтор только владельцу соответствующего запуска.
- Для функций задаётся фиксированный `search_path`; выполнение отзывается у `public` и `anon` и разрешается только роли `authenticated`.
- Секретный ключ Supabase не передаётся в клиент. Браузер получает только публичные URL и publishable key, предназначенные для работы вместе с RLS.

## 5. Порядок анализа и списания

Сервер выполняет действия в следующем порядке:

1. Проверяет действующую сессию пользователя.
2. Проверяет входные данные и Turnstile.
3. Проверяет, что баланс больше нуля, чтобы не выполнять заведомо недоступный запрос.
4. Получает вакансии из источника.
5. Если вакансии получить не удалось, возвращает ошибку без списания.
6. Если вакансии получены, атомарно списывает 1 кредит и создаёт запись запуска.
7. Формирует доступный локальный отчёт и запрашивает улучшенный отчёт у LLM.
8. Если LLM недоступна, вакансии и локальный отчёт остаются доступными. Кредит считается использованным, поскольку анализ рынка уже получен.

Параллельные запросы не могут уменьшить баланс ниже нуля. Если между предварительной проверкой и списанием другой запрос потратил последний кредит, атомарная функция отклоняет второй запуск.

## 6. Кэш и повтор ИИ

- Существующий шестичасовой локальный кэш результатов сохраняется.
- Если результат найден в кэше, API анализа не вызывается и кредит не расходуется.
- Старое ограничение «до 5 новых анализов за 24 часа на один браузер» удаляется: его заменяет серверный баланс Supabase.
- Бесплатный повтор ИИ разрешён один раз для конкретного `analysis_run` и только его владельцу.
- Клиент повторно передаёт уже найденные вакансии вместе с идентификатором запуска; сервер сначала подтверждает владельца и право на повтор, а затем обращается к LLM.
- Повтор не запускает новый поиск вакансий и не создаёт новое списание.

## 7. Обработка ошибок

- Нет сессии: переход на страницу входа или ответ API `401`.
- Нет кредитов: понятное сообщение и ответ API `402`/прикладной код `credits_exhausted`.
- Источник вакансий полностью недоступен: кредит не списывается.
- LLM недоступна: показывается локальный отчёт и доступна одна бесплатная попытка повтора.
- Supabase временно недоступен: анализ не запускается и баланс не изменяется.
- Интерфейс не показывает пользователю внутренние тексты ошибок, токены и конфигурацию.

## 8. Настройка Supabase

Создаётся новый проект на бесплатном тарифе без привязки карты. Для него:

1. Отключается обязательное подтверждение email для учебной демонстрации.
2. Настраиваются локальный и производственный адреса сайта.
3. Применяется версионируемая SQL-миграция с таблицами, триггером, функциями и RLS-политиками.
4. После миграции запускаются проверки безопасности и индексов Supabase.
5. Публичные параметры добавляются в локальное окружение и Vercel; секреты не коммитятся.

Supabase MCP сейчас не подключён к рабочему проекту. На этапе реализации предпочтительно подключить официальный коннектор через авторизацию пользователя. Если он недоступен, тот же результат достигается официальным Supabase CLI или SQL Editor; миграция всё равно хранится в репозитории и остаётся воспроизводимой.

## 9. Проверка готовности

### Автоматические проверки

- Тесты логики ответов API без сессии, без кредитов и при ошибках внешних сервисов.
- Тест того, что успешный новый анализ расходует один кредит.
- Тест того, что сбой источника вакансий кредит не расходует.
- Тест локального кэша и бесплатного повтора ИИ.
- Проверка типов, существующие тесты проекта и производственная сборка Next.js.

### Проверка базы

- Новый пользователь получает ровно 5 кредитов.
- Пользователь видит только собственный баланс и запуски.
- Прямое изменение баланса из клиентской роли запрещено.
- Пять последовательных списаний дают баланс 0, шестое отклоняется.
- Параллельные списания не уводят баланс в отрицательное значение.
- Один бесплатный повтор разрешён, второй отклоняется.

### Сквозная проверка на Vercel

1. Зарегистрировать нового тестового пользователя.
2. Убедиться, что показано 5 кредитов.
3. Выполнить новый анализ и увидеть баланс 4.
4. Повторно открыть тот же сохранённый результат и увидеть баланс 4.
5. Проверить выход и запрет доступа гостю.
6. Проверить сообщения об ошибках и мобильное отображение.
7. Проверить производственные логи без раскрытия секретов.

После успешной проверки изменения отправляются в GitHub, а пользователю передаются рабочая ссылка Vercel и короткий сценарий демонстрации преподавателю.

## 10. Ограничения бесплатной версии и эксплуатация

- Собственный SMTP и подтверждение email пока не настраиваются. Это осознанное упрощение учебной версии.
- Бесплатный проект Supabase может приостанавливаться после периода неактивности. Перед демонстрацией преподавателю нужно открыть Supabase, убедиться, что проект активен, и затем выполнить контрольную регистрацию и анализ на Vercel.
- Платежи, восстановление пароля, OAuth-вход, административная панель, ручное пополнение и 3D-интерфейс не входят в текущий объём.

## 11. Критерий завершения

Работа завершена, когда на производственном адресе Vercel новый пользователь может зарегистрироваться, сразу увидеть 5 кредитов, выполнить пять новых анализов с корректным списанием, не выполнить шестой, выйти и войти снова с сохранённым балансом, а другой пользователь не имеет доступа к его данным.
