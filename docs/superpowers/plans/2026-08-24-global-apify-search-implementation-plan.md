# План реализации глобального поиска через Apify

Дата: 24 августа 2026 года  
Основание: `docs/superpowers/specs/2026-08-24-global-apify-search-design.md`  
Статус: готов к реализации после просмотра пользователем

## Результат

Перевести сервис на единый поток:

`русская форма → Turnstile → английский запрос Apify → реальные вакансии → русский отчёт OpenRouter`.

Прежняя российская интеграция удаляется полностью. Поиск поддерживает конкретную страну или весь мир, готовые профессии выбираются по-русски и отправляются в Apify по-английски, произвольные названия остаются без автоматического перевода.

## Этап 1. Подготовить глобальные справочники

### Действия

1. Создать `lib/domain/job-titles.ts` с 16 согласованными парами русской подписи и английского поискового значения.
2. Добавить чистую функцию `resolveJobTitle`, которая заменяет точное выбранное русское значение на английское и оставляет произвольный ввод без изменения.
3. Создать `lib/domain/countries.ts` со специальным кодом `WORLD` и статическим списком суверенных стран: ISO-код, русское название, английское название и основная валюта.
4. Закрепить согласованные популярные страны в начале экспортируемого списка, остальные отсортировать по русскому названию без повторов.
5. Добавить функции получения страны по коду и валюты по умолчанию.
6. Расширить список валют кодами, реально используемыми справочником стран; валютная конвертация не добавляется.

### Тесты

- `lib/domain/job-titles.test.ts`: готовая профессия преобразуется, произвольная остаётся без изменений.
- `lib/domain/countries.test.ts`: `WORLD` использует USD, все коды уникальны, каждая страна имеет английское имя и валюту, популярные страны находятся в начале.

### Критерий готовности

Справочники не зависят от React, Apify или внешнего API и покрыты детерминированными тестами.

## Этап 2. Расширить схему формы

### Файлы

- `lib/domain/search-schema.ts`;
- `lib/domain/search-schema.test.ts`;
- `lib/domain/job.ts` при необходимости отделить валюту ответа вакансии от валюты формы.

### Действия

1. Заменить СНГ-справочник глобальным списком стран.
2. Разрешить `WORLD` как корректное значение страны.
3. Валидировать страну по встроенному справочнику, а не принимать произвольную строку.
4. Сохранить ограничения длины профессии, города и профиля.
5. Сохранить минимальную зарплату необязательной.
6. Обновить тестовые запросы, использующие старый ограниченный тип страны.

### Критерий готовности

Сервер принимает любую страну из справочника и отклоняет неизвестный код; существующие ограничения безопасности остаются действующими.

## Этап 3. Перестроить Apify input для глобального поиска

### Файлы

- `lib/apify/build-input.ts`;
- `lib/apify/build-input.test.ts`.

### Действия

1. Удалить старую карту только стран СНГ.
2. Перед построением `titleSearch` преобразовывать готовые русские профессии в английские значения.
3. Сохранять дополнительное название отдельным поисковым значением и удалять дубли.
4. Для конкретной страны формировать `locationSearch` из английского названия страны и необязательного города.
5. Для `WORLD` не передавать `locationSearch`, а не отправлять пустую строку.
6. Сохранить лимит 20, период 7 дней и существующие фильтры формата работы и уровня.

### Тесты

- русская профессия и конкретная страна;
- произвольная английская профессия;
- известный русский город;
- неизвестный город с транслитерацией;
- `WORLD` без `locationSearch`;
- дедупликация одинаковых основного и дополнительного названий.

### Критерий готовности

Actor получает только валидные английские значения для готовых вариантов и не получает географический фильтр при глобальном поиске.

## Этап 4. Полностью удалить прежнюю интеграцию

### Удаляемые файлы

- отдельный каталог прежнего источника вместе с реализацией и тестами;
- две исторические спецификации прежней интеграции.

### Изменяемые файлы

- `lib/jobs/search.ts`;
- `.env.example`;
- `README.md`.

### Действия

1. Сделать `lib/jobs/search.ts` тонкой безопасной обёрткой только над Apify.
2. Сохранить преобразование configuration/authorization в безопасный пользовательский код ошибки.
3. Удалить серверную переменную и инструкции прежнего источника.
4. Обновить README: весь мир, английские вакансии, русская аналитика и единственный источник Apify.
5. Выполнить поиск названия, секрета и импортов прежнего источника по исходникам и устранить все совпадения.

### Критерий готовности

В исполняемом коде, конфигурации и пользовательской документации отсутствуют прежний источник и связанные секреты.

## Этап 5. Обновить форму

### Файлы

- `components/market-console.tsx`;
- новый `components/country-combobox.tsx`, если доступный Combobox из уже установленного Base UI подходит текущей версии;
- при необходимости `app/globals.css` только для существующей визуальной системы.

### Действия

1. Для профессии использовать комбинированный ввод с нативным или Base UI списком 16 подсказок и сохранением произвольного текста.
2. Показывать рядом подсказку о предпочтительном английском вводе для собственной профессии.
3. Для страны использовать доступный поисковый Combobox с `WORLD`, популярными и полным списком стран.
4. При смене страны менять валюту на основную валюту выбранной страны.
5. После ручной смены валюты не сбрасывать её до следующей смены страны.
6. При `WORLD` очистить город, отключить поле и показать краткое пояснение.
7. На отправке передавать код страны; преобразование подписей выполняется в доменных модулях и построителе Apify input.
8. Обновить текст пустой выдачи в `app/api/analyze/route.ts` на согласованный глобальный вариант.
9. Обновить метаописание в `app/layout.tsx`, заменив «Россия и СНГ» на глобальный поиск.

### Проверка доступности

- профессия и страна доступны с клавиатуры;
- у полей есть связанные подписи;
- список страны сообщает выбранное значение;
- отключённый город объяснён текстом;
- фокус видим;
- мобильная форма не получает горизонтальную прокрутку.

### Критерий готовности

Пользователь выбирает готовую профессию или вводит свою, находит страну по названию либо выбирает «Весь мир», а форма сохраняет существующий визуальный стиль.

## Этап 6. Сбросить несовместимый браузерный кэш

### Файлы

- `lib/client/history.ts`;
- `lib/client/history.test.ts`.

### Действия

1. Повысить ключ и внутреннюю версию состояния с `v2` до `v3`.
2. Не читать и не мигрировать старые результаты.
3. Обновить тесты кэш-ключа глобальным кодом страны и английским поисковым значением.
4. Сохранить лимит 5 новых анализов за 24 часа и TTL 6 часов.

### Критерий готовности

Старые результаты прежнего источника не появляются в истории; новые Apify-результаты кэшируются как раньше.

## Этап 7. Обновить тестовый набор и выполнить статические проверки

### Действия

1. Удалить тесты прежнего источника вместе с реализацией.
2. Исправить все фикстуры `JobSearch` под новую географию и валюты.
3. Запустить:

```text
pnpm test
pnpm run typecheck
pnpm run build
```

4. Выполнить поиск упоминаний прежнего источника в исполняемых исходниках, README и `.env.example`.
5. Проверить, что ни один секрет не попал в исходники или клиентский bundle.

### Критерий готовности

Все тесты, TypeScript и production-сборка проходят; прежняя интеграция отсутствует в рабочем проекте.

## Этап 8. Проверить локальный пользовательский сценарий

### Действия

1. Запустить локальную production- или development-версию.
2. Проверить форму на desktop и mobile.
3. Проверить готовую профессию с конкретной страной.
4. Проверить вариант «Весь мир».
5. Проверить произвольное английское название.
6. Проверить пустой результат и безопасные сообщения ошибок.
7. Если локальные серверные секреты доступны, выполнить один контролируемый реальный запрос и подтвердить исходные ссылки вакансий.
8. Подтвердить, что вакансии показываются до отчёта, а отчёт остаётся русским.

### Критерий готовности

Полный поток работает локально либо, при отсутствии локальных секретов, все локально проверяемые слои подтверждены и реальный вызов переносится на защищённое окружение Vercel.

## Этап 9. Опубликовать и проверить Vercel Production

### Действия

1. Убедиться, что production-переменные Apify, OpenRouter и Turnstile сохранены в Vercel; значения секретов не выводить.
2. Создать новое production-развёртывание существующего проекта.
3. Дождаться статуса Ready и проверить корневой URL как обычный посетитель.
4. Выполнить один поиск готовой профессии и конкретной страны.
5. Выполнить один поиск по всему миру, учитывая браузерный лимит.
6. Проверить реальные исходные ссылки, русскую аналитику, пустую выдачу и отсутствие упоминаний прежнего источника.
7. Проверить runtime-логи только на безопасные коды ошибок, не публикуя секреты.

### Критерий готовности

Публичный URL проходит полный сценарий `Turnstile → Apify → вакансии → OpenRouter`, а сайт больше не зависит от прежнего источника.

## Порядок безопасного выполнения

1. Справочники и тесты.
2. Схема и Apify input.
3. Удаление HH и упрощение маршрута.
4. Форма и кэш.
5. Полный локальный тестовый набор.
6. Визуальная и реальная проверка.
7. Только затем production-развёртывание.

## Риски и меры

- **Большой список стран:** хранить его в отдельном модуле, проверять уникальность тестом и не дублировать в компоненте.
- **Нестандартная валюта вакансии:** сохранять необязательную валюту ответа и не выполнять конвертацию.
- **Мало результатов по локальной профессии:** показывать подсказку использовать английское название и вариант «Весь мир».
- **Длинный список в мобильной форме:** использовать поисковый доступный Combobox, ограничить высоту списка и разрешить прокрутку.
- **Apify выполняется дольше лимита функции:** сохранить текущий тайм-аут и понятное сообщение, не подставлять фиктивные вакансии.
- **Старая история вводит в заблуждение:** повысить версию кэша без миграции.
- **Production отличается от локальной версии:** после развёртывания обязательно повторить видимый пользовательский сценарий на каноническом URL.
