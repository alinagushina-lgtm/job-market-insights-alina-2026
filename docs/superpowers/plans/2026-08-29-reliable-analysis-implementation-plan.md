# План реализации надежного анализа вакансий

## Цель

Пользователь всегда получает содержательный отчет, если вакансии были найдены. OpenRouter улучшает отчет, но его сбой больше не оставляет экран без анализа.

## Шаги

1. Добавить чистые детерминированные функции:
   - построение резервного отчета по всей выборке;
   - ранжирование и выбор не более 8 вакансий для LLM;
   - сокращение описаний перед отправкой модели.
2. Покрыть эти функции тестами на выборках из 1, 8 и 20 вакансий.
3. Ограничить один запрос OpenRouter 25 секундами и максимум двумя попытками:
   - повторять сетевые ошибки, HTTP 429 и 5xx;
   - повторять один раз ответ неверного формата;
   - не повторять ошибки авторизации и обычные 4xx.
4. Добавить безопасные структурированные логи по этапам без ключей, полного профиля и текстов вакансий.
5. Изменить основной поток `/api/analyze`:
   - отдать вакансии;
   - сразу отдать резервный отчет;
   - затем попытаться заменить его AI-отчетом;
   - при сбое оставить резервный отчет и показать мягкое предупреждение.
6. Добавить `/api/analyze/retry`, который повторяет только AI-анализ по максимум 8 уже найденным вакансиям и не запускает Apify заново.
7. Обновить интерфейс и локальный кэш:
   - явно показывать режим «AI-анализ» или «Резервный анализ»;
   - дать кнопку «Повторить AI-анализ»;
   - сохранить режим отчета в кэше.
8. Проверить тесты, TypeScript и production-сборку.
9. Проверить полный сценарий локально, затем на Vercel Preview и Production, включая искусственный сбой OpenRouter.
10. После успешной публичной проверки отправить код в GitHub.

## Критерий готовности

- При найденных вакансиях на странице всегда есть отчет.
- Сбой OpenRouter завершается за ограниченное время и не удаляет отчет.
- Повтор AI-анализа не расходует повторный запуск Apify.
- В логах можно отличить поиск, резервный отчет, попытки LLM и итоговый режим.
- Публичный production URL проходит успешный и резервный сценарии.
